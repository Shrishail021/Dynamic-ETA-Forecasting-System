# RailPulse — Dynamic ETA Forecasting System
## Operations Runbook & Launch Guide (SIH PS 26028)

**Ministry of Railways | Smart Automation | Theme: Dynamic Train ETA Prediction**

---

## 1. System Overview

**RailPulse** replaces static timetable extrapolation with an autoregressive quantile Machine Learning engine (P50 likely arrival, P90 confidence upper-bound) for Indian Railways coaching trains. It features:
- **Persistent SQLite Database**: Stores rolling stock rosters, timetables, station segments, users, and incoming telemetry records.
- **Dynamic Live Re-Forecasting**: SSE stream dynamically recalculates arrival intervals on every GPS position ping.
- **Operations Control Room**: Dispatcher overview across multiple trains, network corridors, and hazard advisories.
- **Future Prediction Data Store**: Persists live telemetry pings and predictions locally in SQLite and exports standalone `.sql` files for continuous model retraining.

## 3. How to Train & Retrain the ML Models

### Initial Model Training (From Historical Dataset)
The ML models predict section-level running times using only pre-outcome features (leakage-safe).

1. **Train Naive Baseline Model**:
   ```powershell
   cd ml
   py -3.12 train_baseline_model.py
   ```
   *Evaluates the real-world railway standard (schedule + static recovery) across 9,000+ records (~19–21 min MAE).*

2. **Train Autoregressive Quantile GBM Model**:
   ```powershell
   cd ml
   py -3.12 train_gbm_model.py
   ```
   *Trains `HistGradientBoostingRegressor` quantile models (P50 and P90) and saves the bundle to `ml/models/eta_gbm_model.joblib`.*

## 4. Future Prediction Data Store & Retraining Pipeline

> [!NOTE]
> As requested, RailPulse continuously stores new live telemetry pings, departure/arrival events, and dynamic ETA predictions in local storage (`backend/data/railpulse.db`) so newly collected operational runs can improve future predictions.

### How Data is Stored
Incoming pings and predictions are saved to two persistent tables:
- `journey_telemetry_log`: Captures timestamp, speed, current delay, station code, and raw event JSON for every live position ping.
- `predictions_log`: Records all P50 and P90 forecasts generated by the model during operation.

### Option A: Export Telemetry as a Standalone `.sql` File
To inspect or back up collected operational records:
- **From UI**: Navigate to `http://localhost:5173/admin/models` and click **"Download Telemetry SQL Dump"**.
- **From API**: `GET http://localhost:8000/api/telemetry/export.sql` (requires staff/admin token).
- **Direct File**: Generated at `backend/data/telemetry_export.sql`.

### Option B: Retrain Models with Newly Collected Data
To fold new operational runs into the ML model for future prediction:
```powershell
cd ml
py -3.12 retrain_with_new_data.py
```
*This script pulls new arrival events from `railpulse.db`, combines them with the base historical dataset, fits fresh P50/P90 quantile models, and updates `ml/models/eta_gbm_model.joblib` automatically.*


#### 1. Home / Search Radar (`/`)
- **Prominent Search Bar**: Search train number (e.g., `12302`), train name (`Rajdhani`), or station (`NDLS`).
- **Hot Vectors**: Click chips like `12302 Rajdhani` or `12951 Mumbai Rajdhani` to jump straight into live tracking.
- **Tracked Trains Carousel**: Overview of top coaching corridors.
- **3-Step Methodology**: Explains section telemetry, ML regressor, and confidence bands.

#### 2. Browse Trains Directory (`/trains`)
- **Responsive Grid**: Displays coaching trains with type pills, route codes, and live status.
- **Filters**: Filter by Corridor (`R1` Delhi-Mumbai, `R2` Delhi-Amritsar, `R4` Howrah-Delhi, etc.) and Train Type (`Premier`, `Superfast`, `Express`).
- **Live Status Badges**: Shows whether a train is running on-time, delayed, or in critical status.

#### 3. Live Train ETA & Dynamic Re-Forecasting (`/trains/:trainNo`) *(Core Screen)*
- **Route Topology Timeline**: Visualizes the entire route with completed stations, upcoming stations, and an active pulsing transit marker.
- **Next Station Highlight**: Shows the next approaching checkpoint with scheduled arrival clock time.
- **Confidence Band Gauge**: Dual P50 (Likely arrival delay) and P90 (Uncertainty upper bound) visual gradient bar.
- **Active Telemetry**: Displays speed (km/h), section speed limits, block segment ID, and automatic **Speed Anomaly Alerts**.
- **Live Simulation Demo**: Click **"Start Live Demo"** to initiate high-frequency simulated GPS pings (100x/250x/500x speed) with dynamic re-forecasting.
- **Delay Injector**: Manually test hypothetical delay cascades at any station sequence.

#### 4. Operations Control Room (`/control-room`) *(Staff / Dispatcher)*
- Accessible to users logged in as `staff` or `admin`.
- **System KPIs**: Active trains, Network Punctuality Rate %, and Network Average Delay.
- **Multi-Train Matrix**: Birds-eye view showing current station, estimated delay, ML next-station ETA, and section advisories (Fog Zone, Congestion Level).
- **Auto-Sync**: Automatically polls every 10 seconds.

#### 5. Train Master Roster (`/admin/trains`) *(Admin Only)*
- Requires `admin` role.
- **Persistent Roster Table**: View and search all registered trains. Edits persist in SQLite across server restarts.
- **Register New Train**: Click `+ Register New Train` to add a new train number and route corridor.
- **Automatic Timetable Derivation**: The system automatically generates sequential station stops, distances, and running times for newly created trains!
- **Edit & Delete**: Full CRUD with cascade cleanup of schedule stops.

#### 6. Model Performance & Benchmarks (`/admin/models`)
- **Baseline vs. ML Model**: Compares Naive Baseline (~19 min MAE) vs. HistGradientBoosting (~4 min MAE).
- **Empirical Coverage Gauge**: Visual progress bar verifying ~86.4% coverage against the 90% confidence target.
- **Academic Citation Note**: Details the peer-reviewed real-world benchmark (*RSTGCN*, arXiv 2510.01262, 13–15% improvement on real IR data) to demonstrate academic rigor.
- **Telemetry Counter**: Shows the number of logged live pings and predictions.
- **Export Action**: Click **"Download Telemetry SQL Dump"** to export all collected data to a `.sql` file.

#### 7. Control Portal Login (`/admin/login`)
- **Fast Autofill Buttons**:
  - `Admin`: `admin` / `admin123` (Full administration and Train Master CRUD)
  - `Staff`: `staff` / `staff123` (Control room operations and telemetry exports)

## 7. Hard Constraints & Compliance

- **Synthetic Data Compliance**: All pages maintain visible disclaimers in the footer and headers confirming that data is calibrated prototype simulation, not real Indian Railways operational data.
- **Leakage-Safe Modeling**: No post-hoc outcome columns (`actual_running_min`, `speed_anomaly_flag`, `is_tsr_event`) are used as input features during inference or retraining.
- **Secret Management**: JWT secrets and CORS domains are configured via environment variables and `backend/app/core/config.py`.
